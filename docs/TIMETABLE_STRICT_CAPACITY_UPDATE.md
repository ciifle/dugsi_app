# Timetable generator: final strict capacity rule

Implemented for the shared mobile and Web/PWA wizard. Backend, database, and live Swagger were not changed or queried.

1. **Auto-fill root cause.** The committed `_loadSubjects` implementation initialized each controller with `subject.periodsPerWeek`, which came from API `periods_per_week`. It also reloaded subjects after saving. The incoming working tree already contained empty-controller changes, but the post-save reload still discarded current-session entries.
2. **Controller/state fix.** Controllers use `TextEditingController()` with no initial text. `_clearPeriods` disposes controllers and clears subjects, preview, and errors before loading another scope. Request versions discard outdated results. Saving no longer reloads subjects; it retains manually typed values and requests a fresh preview.
3. **New session.** Each dialog creates a new state instance. Closing disposes its controllers. Reopening starts with empty fields, even when the API returns saved requirements.
4. **Level/year reset.** Changing level clears inputs before fetching its subject union. Changing year clears level, inputs, preview, errors, shift, and working days. Returning with **Back to Fix** preserves current-session values.
5. **Shift working days.** GET and PUT include the selected academic year and shift IDs. Changing shift clears visible days before fetching. Response scope checks prevent stale results from populating another selection; saves reload that same shift. Morning and Afternoon remain independent. No capacity is calculated from hardcoded day counts.
6. **Save enablement.** Academic year and level must be selected, subjects loaded, every field explicitly filled with a valid non-negative integer, and no request in progress. Blank never becomes zero. Explicit zero is submitted. Preview readiness does not control this button. Save failure keeps entries and does not request preview; success opens Step 4 and fetches preview.
7. **Preview statuses.** Each class displays backend Requested, Available, Difference, and COMPLETE / UNDER ALLOCATED / OVER ALLOCATED. Under-allocation asks to add the missing periods; over-allocation asks to reduce them. Missing requirements and teacher assignments display their diagnostics and block generation. The level union is not summed into a local class total or filtered into invented curricula.
8. **Strict Generate condition.** Every returned class must be COMPLETE with non-negative, equal requested and available counts, zero difference, no missing requirements/assignments, no expected unscheduled periods, and no rejecting readiness flags. Backend errors or negative overall readiness also block. Legacy summary-only responses cannot authorize generation. There is no Generate Anyway or partial-generation success flow. A backend generation rejection invalidates preview; a capacity/assignment HTTP 409 cannot become a replacement bypass.
9. **Morning tests.** Backend 42 requested / 42 available allows generation; 41 / 42 blocks. Verified at 320px and 1200px widths.
10. **Afternoon tests.** Backend 35 / 35 allows generation; 34 / 35 and 36 / 35 block. Verified at both widths. Mixed Morning/Afternoon class capacities also pass model coverage without a universal capacity constant.
11. **Mobile result.** The existing compact step layout and navy/green styling are retained. Widget tests cover capacity, explicit input, save failure, Back to Fix, year reset, and reopening at 320px. The debug APK builds. No physical-device or live-backend generation run was performed.
12. **Web/PWA result.** The same rules apply in the existing desktop wizard. Tests exercise 1200px layout and success propagation. Successful generation returns `true`; the existing timetable page reloads reference data and timetable rows. The success toast is exactly **Timetable generated successfully.**, replacing queued save notifications.

Existing `test/working_days_shift_isolation_test.dart` was exercised unchanged. Incoming changes in `teacher_day_off_page.dart` were preserved.
